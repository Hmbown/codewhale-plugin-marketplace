# Contributing

Thanks for looking at Computer Use. This is a beta with one macOS target and
experimental ports, so contributions that keep claims honest are worth more
than contributions that add surface area.

## Getting started

```bash
git clone https://github.com/Hmbown/codewhale-cu-plugin
cd codewhale-cu-plugin
npm ci
npm test          # unit, protocol and app tests; no GUI input is performed
```

Node 20 or newer is required. The macOS native helper, practice app and
launcher compile with Xcode Command Line Tools on a Mac; on other platforms
the native tests are skipped and the compiled-helper paths are not exercised.
`npm run build:app` and `npm run install:app` build and install the desktop
app locally; see the README for host configuration.

## What a change needs

- **Tests for behaviour you change.** The suite in `tests/` is the source of
  truth for protocol, session, targeting and update behaviour. Do not weaken
  or skip an existing test to make a change pass; explain the behaviour change
  and update the test instead.
- **Receipts, not assertions, for native claims.** Anything that says a
  platform, toolkit or workflow works must point at a committed, sanitized
  summary in `parity/results/` or a documented reproducible command. Run
  `node scripts/check-receipts.mjs parity/results docs` before committing
  evidence; it rejects home paths, usernames, emails and credential shapes.
- **Documentation that matches the matrix.** README and `docs/LIMITATIONS.md`
  claims must agree with `docs/PARITY_MATRIX.md`, which is generated by
  `npm run parity:matrix` and should not be hand-edited. Untested surfaces stay
  listed as untested.
- **No new session stores or execution loops.** Reuse the daemon, session
  lease and platform-neutral parity runner. `docs/PORTING.md` describes the
  driver and observer contracts for a new platform.
- **Human controls stay human.** Changes must not let a model, environment
  variable or host setting bypass Pause, Stop or an installed helper.
- **Zero runtime dependencies.** The server and helper run on Node alone.
  `sharp` is a build-time dependency for icons only. Dependency updates are
  separate, deliberate changes.

## Platform ports

Windows and Linux are experimental and source-only. Before a port can be
listed as a supported host it needs exact application/window targeting,
native human controls, held-input ownership after a helper crash, a parity
driver with an independent interference observer, and per-platform install,
signing and update qualification. The order of work is in
[docs/PUBLICATION_REVIEW.md](docs/PUBLICATION_REVIEW.md). Pull requests that
advance one of those steps with evidence are welcome; pull requests that only
change the eligibility label are not.

## Pull requests

- Keep each pull request to one concern and describe what was verified, on
  which OS, and what was not.
- CI runs `npm test` and the receipt hygiene check on macOS and Ubuntu. It
  does not sign, notarize or publish anything.
- Releases are qualified and published by hand following
  [docs/RELEASE_CHECKLIST.md](docs/RELEASE_CHECKLIST.md) and
  [docs/DISTRIBUTION.md](docs/DISTRIBUTION.md). Contributors do not need a
  signing identity.
