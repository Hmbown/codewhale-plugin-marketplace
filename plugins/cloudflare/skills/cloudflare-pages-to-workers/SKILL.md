# Cloudflare Pages to Workers

Cloudflare documents a migration from Pages to Workers with static assets
(https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/).
This skill is a checklist for that migration; it does not deploy. Before
changing anything, read Cloudflare's current guide. If the `cloudflare-docs`
plugin is enabled, its docs MCP also publishes a migration-guide tool next to
the search tool.

## 1. Inspect

- `wrangler.toml|json|jsonc` with `pages_build_output_dir`, or a Pages project
  configured only in the dashboard (then there is no config file to convert;
  bindings and variables live in the dashboard and must be re-declared).
- A `functions/` directory (Pages Functions), a built `_worker.js`, `_routes.json`,
  `_headers`, `_redirects`.
- `package.json` scripts that call `wrangler pages dev` or `wrangler pages deploy`.
- Wrangler version: migration needs Wrangler 4 or later
  (`npx wrangler --version`). Upgrading is a normal dependency edit; show it.

## 2. Classify

- **Assets only** (no `functions/`, no `_worker.js`): the new config needs only
  `name`, `compatibility_date` and `assets.directory`.
- **Assets plus code** (a built `_worker.js`, or `functions/`): add `main`
  pointing to the Worker entry, and `assets.binding` (for example `ASSETS`) if the
  code serves assets itself.

## 3. Convert the config

```jsonc
// assets only
{ "name": "my-site", "compatibility_date": "2026-10-01", "assets": { "directory": "./dist" } }

// assets plus code
{
  "name": "my-app",
  "compatibility_date": "2026-10-01",
  "main": "./dist/_worker.js/index.js",
  "assets": { "directory": "./dist", "binding": "ASSETS" }
}
```

- Replace `pages_build_output_dir` with `assets.directory`. Keep bindings
  (`kv_namespaces`, `d1_databases`, `r2_buckets`, `vars`) as they were, with
  real IDs; do not add bindings the project did not already use.
- Keep `compatibility_date` and flags from the Pages config if present.
- A built `_worker.js` must not be uploaded as a public static file. Either move
  it out of the assets directory (Cloudflare's recommendation) or add a
  `.assetsignore` file in the assets directory (gitignore syntax) listing it:

  ```
  _worker.js
  _routes.json
  ```

  Pages excluded `node_modules`, `.DS_Store` and `.git` automatically; Workers
  does not, so list them (`**/node_modules`, `**/.DS_Store`, `**/.git`) if they
  are inside the assets directory.
- `_headers` and `_redirects` placed in the assets directory are parsed by
  Workers and keep working for static asset responses, so do not ignore them.
  They are not applied to responses generated by Worker code; if the project has
  Pages Functions, `_worker.js`, or `run_worker_first`, headers and redirects for
  those responses must be set in code.
- If `functions/` exists, the build must compile it. Cloudflare's guide adds
  `wrangler pages functions build --outdir=<assets-dir>/_worker.js/` to the build
  script, and `main` then points at that output. Confirm the exact flags with
  the current docs before editing.

## 4. Scripts

| Before | After |
| --- | --- |
| `wrangler pages dev <dir>` | `wrangler dev` |
| `wrangler pages deploy <dir>` | `wrangler deploy` (needs approval) |

Framework commands (`astro dev`, `next dev`) stay as they are. If the framework
has a Cloudflare adapter that supports Workers, use its documented setup.

## 5. Validate locally

1. Build with the project's command.
2. Run `/cloudflare-preflight`.
3. `npx wrangler deploy --dry-run` and read its output for the asset count, the
   entry file and bindings.
4. `npx wrangler dev`, then request the routes that the old site served,
   including a missing path, an SPA route if applicable, and one Function route.

## 6. Cutover is the user's call

Deployment, custom-domain changes and deleting the Pages project are
account-level actions. Follow `cloudflare-deploy`: show the plan and wait for a
yes. Things to tell the user before cutover:

- Preview deployments, branch aliases and the `*.pages.dev` hostname do not
  carry over automatically; Workers Builds and `workers.dev` work differently.
- Custom domains must be attached to the Worker, and that moves traffic.
- Keep the Pages project until the Worker is verified; do not delete it.

## Done means

The config converts, a dry run succeeds, `wrangler dev` serves the expected
routes, and the report lists what still needs the user (dashboard-only bindings,
domains, cutover).
