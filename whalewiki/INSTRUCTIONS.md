# Extension repository wiki brief

- Audience: contributors choosing where an extension belongs and operators
  deciding what they can actually install or run.
- Cover: catalog admission, package review, WhaleWiki evidence semantics,
  shared runtime ownership, connections versus inbound bots, and failure recovery.
- Cite concrete source files and symbols. A seal means unchanged bytes, not
  correctness. Keep local tests, hosted CI, account login and live bot behavior
  separate in any readiness statement.
- Skip: copied service documentation, credential values, runtime receipts,
  unrelated Core release work, and claims that every listed service is qualified.
- Update a page only after reading its changed source basis; discover new
  modules with a new scan. Keep the page set small and useful.
